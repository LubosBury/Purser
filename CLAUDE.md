# Purser

Native macOS app (SwiftUI) for reviewing and applying price changes in App Store Connect. The app, the code and the docs are in English. The milestone plans in `docs/plans/` are private, Czech and gitignored; never commit them or link to them. Start with `README.md`.

## Build and test

- `make test` runs the PurserCore package tests (Swift Testing). Every commit keeps them green.
- `make build` builds the app unsigned (compiles, cannot sign in). `make build-signed` needs `Config/Signing.local.xcconfig` (gitignored) and is the only build that can sign in, use the Keychain and reach App Store Connect.
- `make release` builds the Developer ID app, notarizes it and packs a DMG into `build/release/`; it needs a clean tree and the `purser-notary` keychain profile. This is the build users download.
- `make check-endpoints` checks every ASC path listed in `docs/research/asc-api-paths.md` against Apple's OpenAPI spec; add a new path there when code starts calling it.
- `python3 -I -m unittest discover -s Tools/tests` runs the tool tests.
- `PURSER_BENCH=1 swift test --package-path Packages/PurserCore --filter PlanOpenBenchmark` times the steps of opening a plan (skipped in `make test`). In a DEBUG app, `PlanOpenTrace` logs the same steps under the `plan-open` log category.
- The Xcode project is generated by XcodeGen from `project.yml`; never edit `Purser.xcodeproj`.

## Write safety (do not weaken)

- Only code in `Packages/PurserCore/Sources/Executor` writes to App Store Connect: `Executor` (plans), `ProductCreator` (groups, subscriptions, non-consumables) and the DEBUG `SpikeProbe`. `ArchitectureTests` enforces it, and that a write-capable client (`readOnly: false`) is built only in `App/Session/WorkspaceSession+Apply.swift` and `WorkspaceSession+SpikeProbe.swift`.
- `AppGuard` refuses anything outside the workspace app; a new endpoint needs its rule and tests there first.
- Every write is audited before it leaves (`httpSent`) and after it returns (`httpReceived`), asks for Touch ID, and is never retried automatically.
- The ASC API has no sandbox. Tests run against `FakeASC`; its behaviour is an assumption until a spike in `docs/spikes/` confirms it. Live trials go only to the never-submitted "Purser Spike" group.
- The Swift module for Keychain, JWT and Touch ID is `PurserSecurity` (folder `Sources/Security`); a target named `Security` breaks the build.

## Layout gotcha

`NavigationSplitView` must be the root view of the workspace window. With anything stacked above it (a banner in a `VStack`), macOS draws the top strip of the detail column under the toolbar material and the screen's own controls disappear. Banners go inside the detail column or in a bottom `safeAreaInset`.

Do not use `.inspector` inside the detail column. Even while hidden it adds its column to the split view's minimum width; the window root's `.frame(minWidth:)` then centers the oversized split view and clips the sidebar and the right edge. Side content goes in a sheet (see the cell history in `CatalogView`).

Do not put a `DisclosureGroup` inside a row with `.fixedSize(horizontal: false, vertical: true)` next to a `Table`. The row's minimum height inflates, the screen becomes taller than the window and is centered, so the header, the sidebar items and the bottom action bar end up outside the window. Give panels an explicit height and put details in a popover (see `PlanView`).

In a `List(selection:)`, apply `.badge` before `.tag`. A row written as `.tag(x).badge(n)` cannot be selected (this made Findings and Plans unreachable from the sidebar).

## UI rules

Every screen follows these rules. Shared pieces: `App/Shared/Design/PurserComponents.swift` (badge, glass panel, stage, buttons, table, the gate card for the owner name, lock and the workspace picker, settings panels) and `App/Plans/PlanFormParts.swift` (numbered form steps, fields, messages; also used by the workspace and product sheets).


- The look is defined in `docs/design/README.md` (brand book) and `docs/design/components/*.md` (one guideline per component, each with its SwiftUI counterpart). Read them before building or changing any view.
- Colors, spacing, radii and fonts come from `PurserColor`, `PurserSpacing`, `PurserRadius` and `PurserFont` in `App/Shared/Design/PurserTokens.swift`. Never hard-code a color, size or font in a view. If a value is missing, it needs a token first.
- Native controls first (`Button`, `Table`, `Picker`, `Toggle`, `List` sidebar, `.sheet`). Glass is `.glassEffect` in a `GlassEffectContainer` on macOS 26, `.ultraThinMaterial` before that, over a black window. Reduce Transparency and Reduce Motion must work.
- The app is dark only: `.preferredColorScheme(.dark)` on the window group.
- Status is never color alone: BLOCK, WARN and Verified carry a word and a differently shaped icon.
- Every user-facing text is English, written as a plain string literal (no string catalog). Prices and percentages format with the `en_US` locale.

## Design tokens workflow

`App/Shared/Design/PurserTokens.swift` is generated. Do not edit it.

1. Change the token in the Purser design system artifact (https://claude.ai/artifact/LnqRwNwSPj7UYJr3ZCjqfD, private to the owner).
2. Copy its `tokens.json` (and any changed README or component guideline) into `docs/design/`.
3. Run `python3 -I Tools/generate-design-tokens.py` and commit the diff.
4. `python3 -I Tools/generate-design-tokens.py --check` fails when the Swift file is out of date.

If the artifact is not reachable, `docs/design/` is the source of truth until it is.
